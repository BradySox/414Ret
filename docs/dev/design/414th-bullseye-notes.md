# Bullseye placement (§95)

Built 2026-08-24. Fork-only. Upstream code is `Game.set_bullseye`; this replaces it.

## What upstream does

`Game.set_bullseye` runs inside every `initialize_turn`:

```python
player_cp, enemy_cp = theater.closest_opposing_control_points()
blue.bullseye = Bullseye(enemy_cp.position)
red.bullseye = Bullseye(player_cp.position)
```

Each side's bullseye is planted on the *other* side's nearest control point, and the
whole thing is re-derived from scratch on every turn init.

`initialize_turn` is not once a turn. It also runs on cheat capture, on a front-line
move, and on any TGO buy or sell — so the bullseye could move several times inside one
turn.

## What was measured

Four local saves, loaded headlessly (`tools`-free probe, `persistency.setup` +
`load_game`), 2026-08-24:

| Save | Blue bullseye anchored on | Problem |
|---|---|---|
| `autosave` (Marianas, t1) | `CV 1143.5 Admiral Kuznetsov` | a red **carrier**, in open water |
| `Maybe 414` (Caucasus, t1) | Khashuri FOB | 5 of 19 blue packages within 10 NM; one at **0.0 NM** |
| `test 1` (Syria, t1) | King Abdullah II | 5 of 30 packages within 10 NM |
| `test` (Syria, t2) | King Abdullah II | 5 of 31 packages within 10 NM |

Three defects follow:

1. **A bullseye can be a ship.** `player_points()` / `enemy_points()` include fleets, so
   a carrier or LHA is an eligible anchor. Blue's own carrier is player-draggable
   (`PUT /controlpoints` sets `target_position`, applied in `ControlPoint.process_turn`),
   so repositioning your own boat moved *red's* bullseye.
2. **An off-map spawn is eligible.** Caucasus carries a `Turkey` `OffMapSpawn`. It never
   won the distance check on the saves measured, but nothing excluded it.
3. **It never stays put.** A squadron memorizes one bullseye and reads it off the
   kneeboard for weeks. Upstream's re-derivation moves it whenever the nearest opposing
   pair changes — which a base capture or a front-line shift does routinely.

## What it does now

Two rules, both in `Game.set_bullseye` → `ConflictTheater.bullseye_anchors` +
`Coalition.anchor_bullseye`.

**The anchor cannot be a boat or an off-map spawn.** `bullseye_anchors()` runs the same
nearest-opposing-pair search as `closest_opposing_control_points()` over a filtered
candidate list. A side that has *nothing* else falls back to its full list — a bullseye
on a boat beats an assertion. `closest_opposing_control_points()` itself is unchanged, so
`AirConflictDescription` keeps upstream's conflict centre.

**The pin is for the campaign, not the turn.** `Coalition.anchor_bullseye` keeps the
existing point unless it has drifted more than `MAX_DRIFT` (80 NM,
`game/theater/bullseye.py`) from where it would be re-derived now. Repeated
`initialize_turn` calls inside one turn are idempotent.

**The kneeboard names the place.** `Coalition.bullseye_anchor_name` records the control
point the bullseye is planted on, and `BriefingPage._bullseye_line()` renders one row
carrying all three facts:

```
Bullseye: King Abdullah II — 32°00'20"N 36°13'25"E
Bullseye: FOB Agrihan — 18°46'34"N 145°39'52"E   ** MOVED THIS TURN **
```

`Coalition.bullseye_moved_on_turn` records the turn a pinned bullseye actually changed
position; the banner appears only when it matches the current turn. A campaign's own
first pin is not a move, and a re-anchor that lands on the same point is not a move.

**It is one line, not two.** The BLUF's duplicate BULLSEYE line was struck on the brief
sheet rework (`414th-features.md` §4) in favour of upstream's post-flight-plan row. Do
not add a second one; put anything new on `_bullseye_line()`.

Nothing is authored per campaign. The DM's call (2026-08-24): the point is generated by
the app so it works on any future campaign without a yaml edit.

## Save migration

`Coalition.__setstate__` defaults `bullseye_pinned` to **False**, not True. A pre-pin
save's bullseye was re-derived every turn and may be sitting on a boat, so it re-anchors
once under the new rule and is pinned from then on.

Measured on the four saves: the three land campaigns re-anchor **in place** (0.0 NM, no
banner); Marianas moves blue's bullseye **61.4 NM** off the Kuznetsov onto FOB Agrihan
and prints the banner once. All four are stable across five further turn inits.

## Considered and not done

- **A campaign yaml `bullseye:` pin.** Offered and declined — the point must be generated
  so future campaigns need no authoring.
- **Standing the bullseye off the anchor field by 20–30 NM.** Would fix the 0.0 NM
  resolution case (a package fragged against the anchor base itself calls
  "bullseye 000 for 0"). Not taken: it trades away the one thing that makes a bullseye
  findable — sitting on a named field you can pick out on the F10 map. Open if the
  degenerate calls turn out to matter in the air.
- **A `Settings` knob for `MAX_DRIFT`.** 80 NM is a module constant. Promote it if a
  campaign is found where it is wrong; nothing has needed it yet.
- **A SITREP line for the move.** The kneeboard banner is the surface that reaches the
  cockpit. A §29 SITREP field would need a new frozen-dataclass member for a once-per-
  many-turns event.
- **A second, more prominent bullseye line.** See "It is one line, not two" above.

## Traps

- **`MAX_DRIFT` is measured against the current anchor candidate, not the front line.**
  It answers "would re-deriving move it far?", which is the question that matters.
- **The fallback in `anchor_bullseye` is deliberate.** A carrier-only coalition keeps a
  boat anchor rather than raising; do not turn it into an exception.
- **Do not make `closest_opposing_control_points` filter.** Its other caller
  (`AirConflictDescription.for_theater`) wants the true nearest pair, boats included.
